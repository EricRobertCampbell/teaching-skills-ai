# Review Math 30-1 Unit (Assessment Package)

Review an entire unit’s **graded assessment package** — typically all **daily quizzes**, **quizzes**, and **assignments** for that unit (include a unit test if present).

This skill is **not** a substitute for single-component review: it runs each component through **review-math-30**, then adds **cross-assessment** checks.

## Prerequisite

Read and apply **`skills/review-math-30/SKILL.md`** first. Every component in the package must satisfy that skill’s general checks and component checks (curricular objectives, difficulty-by-points, timing).

## Workflow

1. Inventory the package: list each daily quiz, quiz, assignment (and test if included), with total points and claimed topics/outcomes.
2. For **each** component, run the full **review-math-30** workflow and record findings.
3. Run the **unit-level checks** below across the whole set.
4. Report per-component issues first, then unit-level issues; prefer concrete fixes (move/cut/add items, reweight, retarget outcomes).

## Report format

Use the same severity bands as **review-math-30**:

- **Must fix**: incorrect math / unfair component; major outcome overweight or missing; clear duplication; large hole in coverage
- **Should fix**: mild imbalance, near-duplicate items, soft under-assessment of a secondary topic
- **Optional**: polish, alternate forms, enrichment placement

Structure the report as:

1. **Per component** — findings from review-math-30 (cite file / question numbers)
2. **Unit overview** — points map by outcome/topic; difficulty mix across the package
3. **Unit-level issues** — weight, balance, duplication, gaps (with suggested redistributions)

## Unit-level checks

### Outcome / topic weight

- Map every scored item in the package to unit outcomes / topics
- Sum points (and, if useful, item counts) per outcome across **all** assessments
- Flag any part of the unit with **too much** or **too little** weight relative to instructional emphasis and curricular importance
- A major outcome should not live only on a short daily quiz while a minor skill dominates the quiz/assignment marks

### Balance across assessments

- Assessments **as a whole** should be balanced: variety of formats (when intended), difficulty bands by points, and progression (DQ → quiz → assignment) that matches how the unit is taught
- No single assessment should carry almost all the high-stakes hard marks, or almost none of them, unless intentional
- Daily quizzes stay short (&lt; 10 min); quizzes stay completable in 40–60 min for weaker students; assignments &lt; 60 min open-book — if the package as a whole overloads students in a week, note that even when each piece is individually OK

### Duplication

- Check that there is **not** duplication of questions between assessments (same stem, trivial number-swap of the same task, or the same skill exercised the same way for the same marks)
- Near-duplicates that teach a progression (scaffold → independent) are OK if intentional and not double-counting the same evidence for the same outcome without purpose — call those out as **Should fix** / **Optional** rather than ignoring them
- Practice worksheets are outside this package unless the user includes them; do not flag DQ/quiz vs worksheet overlap unless asked

### Coverage gaps

- Flag **parts of the unit that are not assessed** (or only assessed trivially) anywhere in the package
- Distinguish intentional omissions (e.g. enrichment, deferred to the unit test) from accidental holes
- If a unit test is missing from the package, note outcomes that appear only on instruction/worksheets and recommend where they should land (DQ, quiz, assignment, or test)
